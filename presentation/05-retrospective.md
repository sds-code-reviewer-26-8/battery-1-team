# 5. 회고

Loop를 직접 설계하고 구현하며, 코드와 Diff 요약, Report 등의 Evidence를 리뷰하는 방식으로 팀 프로젝트를 진행했습니다.

이번 팀 프로젝트를 진행하면서 느꼈던 점을 팀원별로 적어 주세요.

| 팀원 이름 | 좋았던 점 | 아쉬웠던 점 |
|---|---|---|
| 권웅기 | - AI를 사용해서 개발부터 코드리뷰까지 모든 과정을 경험해 볼 수 있었습니다.<br>- Skill을 직접 만들어서 구현 내용에 대한 준비부터 검증까지 처리해 볼 수 있었습니다.<br>- 팀원들 간 리뷰 소통에도 AI를 사용하니 더 빠르게 요점을 파악할 수 있었습니다. | - AI가 수정한 코드 양에 비해 검증할 수 있는 시간이 부족해서 화면 동작으로만 확인하는 경우도 있었습니다.<br>- 잘못된 Loop를 설계했을 경우 수정하는 프로세스에 대한 고민이 더 필요할 것 같습니다. |
| 김도현 | - Agent를 이용해서 처음 보는 프로젝트의 이해부터 리팩토링 과정까지 경험해 볼 수 있어서 좋았습니다.<br>- Claude를 통해서 Git을 사용하는 경험을 할 수 있어서 좋았습니다.<br>- 리팩토링 개선 제안을 Agent한테 받아보고 이를 반영해서 코드가 개선되는 것을 경험할 수 있었습니다.<br>- Loop에 대해 처음 접해 보았고, Loop 설계를 직접 해보고 이를 팀 프로젝트에 적용시킬 수 있었습니다.<br>- 팀 프로젝트 과정에서 팀원분들께 코드 피드백을 받아보고 이를 반영해서 프로젝트가 개선되는 경험을 할 수 있어서 좋았습니다.<br>- JMeter, Playwright를 통해서 성능 테스트, E2E 테스트를 수행하는 것을 배울 수 있어서 좋았습니다. | - 실제로 업무에서 사용되는 Loop 사례들을 더 다양하게 접하면 좋았을 것 같습니다.<br>- 코드리뷰 교육 기간이 2주로 이전보다 짧아져서 아쉬운 부분인 것 같습니다. |
| 김재연 | - 시대에 맞춰 AI를 코드 리뷰에 활용하는 방법을 배워서 좋았습니다. 세부 작업은 AI에게 맡기고 저는 판단과 확인에 집중하면서, 팀 단위 협업이 어떤 흐름으로 이어지는지 익힐 수 있어 유익했습니다.<br>- 리뷰를 주고받는 방법을 배웠습니다. GitHub에서 직접 리뷰를 남기고 팀원들의 코멘트를 읽으면서, 작성자가 부담 없이 받아들이고 리뷰어도 이해하기 쉬운 코멘트가 어떤 모습인지 알게 됐습니다.<br>- 반복 작업을 구조화하는 방법을 배웠습니다. 루프 같은 방식으로 반복되는 작업을 정리해서 낭비되는 시간을 줄일 수 있다는 것을 경험해서 좋았습니다. | - 프로젝트 기간이 짧아 리뷰 지적 사항 중 일부를 바로 반영하지 못하고 후속 이슈로 넘긴 점이 아쉬웠습니다.<br>- 루프를 구성하는 상황별 예시를 더 다양하게 접할 수 있었다면 개념을 이해하고 실제 작업에 적용하는 데 도움이 됐을 것 같습니다. |
| 김준영 | **혼자 쓰던 Loop를 팀 안에서 점검해 볼 수 있었다**<br>현업에서 하네스·Agent Loop를 혼자 써서 과하거나 부족한 부분을 알 수 없었습니다. 강의 템플릿에 필요한 것만 더했더니 가볍게 잘 돌아가는 것을 알 수 있었습니다.<br><br>**AI Skill로 깊이 있는 PR 리뷰를 경험했다**<br>현업에서는 일정 때문에 merge 후 테스트하기 바빴습니다. 이번에는 `/pr-explain`, `/pr-review`, `/code-review`로 PR을 분석하고 리뷰할 수 있었습니다.<br><br>**팀원과 서로의 코드를 리뷰하고 개선했다**<br>리뷰 의견을 보고 개선하는 경험이 좋았습니다. | **일정이 짧아 경험이 제한적이었다**<br>3주를 유지하거나 1~2일 더 늘려 다양한 팀 프로젝트를 해 보면 좋았을 것 같습니다.<br><br>**내 Loop가 잘 만들어졌는지 판단하기 어려웠다**<br>Loop를 평가하고 보완하는 방법을 충분히 알지 못해 아쉬웠습니다. |

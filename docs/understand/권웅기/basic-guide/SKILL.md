# 코드 입문자용 HTML 이해 문서

코드를 처음 보는 사람이 적은 에너지로 단계별로 이해하고, 나중에 코드 리뷰를 편하게 하도록 돕는 문서를 만든다.

## 0. 시작 전에 반드시 묻기

문서를 쓰기 전에 사용자에게 아래를 먼저 묻는다. 답을 받기 전에는 쓰지 않는다.
**AskUserQuestion 도구는 쓰지 않는다.** 선택 팝업이 진행을 막는 경우가 있으므로, 번호가 붙은 보기를 일반 대화 텍스트로 보여 주고 사용자가 번호나 말로 답하게 한다. 답이 없거나 "아무거나"면 괄호 안의 기본값으로 진행한다.

1. **독자:** 누가 읽는가? (1 비개발자 [기본] / 2 다른 업무 도메인의 개발자 / 3 신입 개발자 / 4 직접 입력)
2. **리뷰 중점:** 어디에 무게를 둘까? 복수 선택 가능. (1 계산·업무 규칙 정확성 [기본] / 2 동시성·데이터 정합성 / 3 보안 / 4 코드 품질)

두 질문을 한 메시지에 함께 보여 주고, "예: 1번, 1·2번"처럼 답하는 방법도 적어 준다.

독자가 비개발자면 코드 용어를 쓰지 않는다. 개발자면 용어를 쓰되 처음 나올 때 한 줄로 풀어 준다.

## 1. 원칙

- 요구사항(업무)을 먼저, 코드는 나중에. 첫 화면에는 코드 용어를 쓰지 않는다.
- 위에서 아래로 갈수록 깊어진다. 앞부분만 읽어도 윤곽이 잡혀야 한다.
- 용어는 처음 나올 때 풀어 쓴다. 별도 용어집 페이지는 두지 않고 `<abbr title="뜻">` 으로 마우스를 올리면 보이게 한다.
- 코드에서 직접 확인한 내용만 쓴다. 추측은 "확인 필요"로 표시한다.
- 추상적 설명 대신 실제 숫자 예시를 쓴다. 예: "중국 5,000K 주문 → 재고 한도 4,000K → 2번 방문".

## 2. 문서 구성 (이 순서로 고정)

| 순서 | 섹션 | 내용 | 분량 |
|---|---|---|---|
| 1 | 3줄 요약 | 중학생도 이해할 수준 | 3줄 |
| 2 | 누가, 무엇을 하나 | 사용자와 업무 흐름을 가로 화살표 도식으로 | 화면 반 장 |
| 3 | 업무 규칙 | "이렇게 계산한다" 목록 | 5~10줄 |
| 4 | 지도 | 파일·폴더별 역할 표, 요청 흐름 도식 | 표 1, 그림 1 |
| 5 | 핵심 동작 따라가기 | 예시 하나를 처음부터 끝까지 단계별 카드로 추적 | 카드 4~7장 |
| 6 | 리뷰 포인트 | 0단계에서 고른 중점에 맞춘 "여기를 의심해 보세요" 체크리스트 | 목록 |

## 3. 읽기 쉽게 만드는 장치

- 상세 내용은 `<details>` 로 접어 두고, 기본은 요약만 보이게 한다.
- 코드 인용은 `파일:줄번호` 로만 표시한다. 코드 블록은 접힌 "자세히 보기" 안에 둔다.
- 좌측 목차를 고정(sticky)하고 현재 위치를 강조한다.
- 흐름은 화살표로 이어진 상자로 그린다. 외부 라이브러리 없이 HTML/CSS 로만 만든다.
- 밝은/어두운 테마를 모두 지원하고, 모바일 폭에서도 가로 스크롤이 생기지 않게 한다.
- 한 문장은 짧게. 한 섹션은 화면 한두 장을 넘기지 않는다.

## 4. 작업 순서

1. 0단계 질문으로 독자와 리뷰 중점을 정한다.
2. 코드를 읽고 업무 규칙, 사용자 흐름, 파일 역할, 대표 시나리오 하나를 뽑아낸다.
3. 위 구성에 맞춰 **HTML 한 파일**(CSS, JS 인라인)로 작성한다.
4. 아래 경로에 저장한다.
5. 저장 후 사용자에게 파일 경로와 한 줄 요약만 알린다. 문서 내용을 대화에 다시 풀어 쓰지 않는다.

## 5. 저장 위치

`docs/` (프로젝트 루트 기준). 공용 저장소이므로 하위 폴더를 만들지 않고 `docs/` 바로 아래에 둔다. 폴더가 없으면 만든다.
파일명은 `<대상>-understand.html` (예: `battery-understand.html`). 같은 이름이 있으면 덮어쓰기 전에 사용자에게 확인한다.

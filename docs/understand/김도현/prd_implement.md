# PRD — 배터리 주문·생산·선박 운영 계획 프로그램

## 1. 개요

해외 4개국(중국·일본·베트남·인도네시아) 공장에서 만든 배터리 셀을 배로 한국에 가져오는 계획을 계산해 주고, 담당자가 고른 계획을 주문으로 확정·관리하는 웹 애플리케이션이다. 주문 수량을 넣으면 공장별 생산과 선박 운항 계획을 비용·기간과 함께 비교해 볼 수 있다.

업무 배경 (요구사항 원문 기준)
- DSD는 한국 본사의 배터리 생산·공급 기업이고, 전기차용 원통형 **2170 셀**을 만든다. 차량 1대에 약 4K개가 들어간다.
- 중국·일본·베트남·인도네시아 4개국에서 공장을 직접 소유·운영하고, 모든 공장이 같은 배터리를 만든다.
- 주문이 접수되면 가능한 빨리 생산을 시작해 각 공장의 완제품 재고 창고에 보관한다. 공장마다 하루 최대 생산량, 재고 보관 용량, 생산원가가 다르다.
- 임차한 화물선 1~4척으로 한국에 들여온다. 선박은 하루 대당 약 1억 원이고, 한국 항만에 정박 중에는 비용이 없다. 컨테이너 적재량은 충분하다.

## 2. 사용자

주문 담당 관리자. 주문을 입력하고, 경로를 비교해 확정하고, 주문 상태를 바꾸고, 마스터 데이터를 관리한다.

## 3. 범위

포함: 마스터 데이터 관리, 경로 시뮬레이션, 주문 확정, 주문 조회, 주문 상태 관리

## 4. 용어

| 용어 | 뜻 |
|---|---|
| K | 1,000개. 주문·생산·재고 수량의 단위 (예: 15,000K = 약 1,500만 개) |
| 마스터 데이터 | 계산의 기준 값. 공장별 하루 생산량·재고 상한·셀당 원가, 나라 간 항해 일수, 배 척수·하루 운항비 |
| 마스터 버전 | 마스터를 저장할 때마다 오르는 번호. 시뮬레이션 이후 바뀌었는지 판단한다 |
| 재고 상한 | 공장 창고가 보관할 수 있는 최대 수량(K). "창고 한도"와 같은 말이다 |
| 경로(안) | 선박을 어떻게 운영할지에 대한 계산 결과 하나 |
| 소요 일수 | 마지막 배가 한국에 돌아오는 날 |

## 5. 핵심 업무 흐름

수량 입력 → 경로 비교 → 하나 골라 확정 → 상태 관리(확정 → 진행 → 완료)
마스터 데이터(공장 생산 능력, 항해 일수, 운항비)를 관리하면 그 뒤의 계산부터 반영된다.

## 6. 기능 요구사항

### FR-1. 마스터 데이터 관리
- 공장별 하루 최대 생산량, 재고 상한, 셀당 생산원가를 관리한다.
- 나라 사이의 항해 일수를 관리한다.
- 배 척수와 배 하루 운항비를 관리한다.
- 잘못된 값이 하나라도 있으면 저장하지 않고 이유를 알려 준다.
- 저장할 때마다 마스터 버전이 오른다.
- 바꾼 값은 그 뒤의 계산부터 적용된다. 이미 확정한 주문은 그대로다.

### FR-2. 경로 시뮬레이션
- 공장별 수량을 입력하면 서버가 여러 경로안을 계산해 한 번에 비교해 보여 준다.
- 경로마다 소요 일수, 생산비, 운항비, 배별 방문 일정을 보여 준다.
- 입력은 공장별 수량이며, 음수는 불가하고 총합은 1K 이상 100,000K 이하여야 한다. 수량이 하나도 없는 주문은 계산하지 않는다.
- 주문 추가 화면에 '가능한 빨리' 체크박스가 있고 기본은 해제 상태다. 체크하면 납기일 입력칸이 나타나며, 납기일은 5일 이상 50일 이하의 정수만 받는다. 범위를 벗어나면 오류를 알리고 표시를 적용하지 않는다.
- 납기일이 있으면 소요 일수가 납기일보다 긴 경로는 경로 비교 카드에 빨간색과 초과 일수로 표시하고, 선택한 경로의 소요 일수도 초과하면 빨간색으로 표시한다. 납기일을 바꾸거나 체크를 해제하면 시뮬레이션을 다시 실행하지 않아도 바로 반영된다.
- 납기일은 화면에서 확인용으로만 쓰며 주문에 저장하지 않는다. 납기를 넘는 경로도 주문 확정은 가능하다.

### FR-3. 주문 확정
- 마음에 드는 경로를 골라 주문으로 확정한다.
- 확정 직전에 서버가 같은 입력으로 다시 계산한다. 화면이 보낸 숫자를 믿지 않는다.
- 시뮬레이션 후 마스터가 바뀌었으면 확정을 거부하고 다시 시뮬레이션하게 안내한다.
- 확정한 주문에는 그 시점의 마스터 값과 계획 전체를 함께 저장한다. 마스터가 나중에 바뀌어도 옛 주문의 내용과 비용은 변하지 않는다.

### FR-4. 주문 조회
- 확정한 주문을 목록과 상세 화면으로 본다.
- 상세에서 확정 당시의 계획과 상태 변경 이력을 확인할 수 있다.

### FR-5. 주문 상태 관리
- 상태는 확정 → 진행 → 완료 순서로 진행한다. 확정·진행 상태에서는 취소할 수 있다.
- 완료와 취소는 마지막 상태라 더 바꿀 수 없다.
- 상태를 바꿀 때마다 이전 상태, 새 상태, 변경자, 시각을 이력에 남긴다.
- 두 사람이 같은 주문을 동시에 바꾸면 한쪽의 변경만 반영하고, 다른 쪽에는 새로고침 후 다시 시도하라고 안내한다. (낙관적 락)

| 상태 | 의미 (요구사항 원문) |
|---|---|
| 확정 | 고객사와 소통되어 주문을 구두로 확정한 상태 |
| 진행 | 계약서를 작성 후 공장 생산 및 운영을 시작한 상태 |
| 완료 | 생산이 완료되어 한국으로 물량이 모두 들어온 상태 |
| 취소 | 어떤 사정으로 인해 취소된 상태 (확정 / 진행 중에 취소 가능) |

### FR-6. 금액 표시
- 금액은 화면에 억 원 단위로 보여 준다.

## 7. 업무 규칙 (계산의 기준)

1. 생산은 주문 즉시 모든 공장에서 동시에 시작한다.
2. 공장은 하루 최대 생산량까지만 만들고, 재고 상한을 넘게 쌓지 못한다. 창고가 차면 배가 가져갈 때까지 생산이 멈춘다.
3. 배는 도착한 순간 쌓여 있는 재고를 전부 싣는다. 선박 적재량은 제약이 아니다.
4. 주문이 재고 상한보다 많으면 여러 번 방문한다. 방문 횟수 = 올림(주문 ÷ 재고 상한). 주문이 없는 나라는 가지 않는다.
5. 여러 번 방문할 때는 한국에 돌아와 짐을 내리고 다시 출항한다. 배는 한국에서 출발해 한국으로 돌아온다.
6. 배는 재고가 채워지는 날에 맞춰 가능한 한 늦게 출항한다. 한국에서 기다리는 시간은 비용이 없다.
7. 생산비 = 주문 수량(K) × 1,000 × 셀당 원가
8. 운항비 = 배가 바다에서 보낸 날수 × 하루 운항비 (항구 대기일 제외)
9. 총 비용 = 생산비 + 운항비

## 8. 데이터 요구사항

- 생산 수량은 K, 금액은 원 단위 정수로 저장하고, 억 원 변환은 표시할 때만 한다.
- 확정한 주문은 그 시점의 마스터 값과 계획을 함께 저장하고, 이후 마스터가 바뀌어도 변하지 않는다.

## 9. 비기능 요구사항

| 항목 | 내용 |
|---|---|
| 정합성 | 확정은 서버 재계산 결과만 믿는다. 클라이언트가 보낸 값은 신뢰하지 않는다 |
| 동시성 | 같은 주문을 동시에 바꾸면 한쪽을 거부한다 (낙관적 락) |
| 오류 안내 | 사용자 입력 오류는 이유를 쉬운 한국어로 알린다 |

주문 목록, 주문 추가(수량 입력·시뮬레이션·확정), 주문 상세, 마스터 데이터

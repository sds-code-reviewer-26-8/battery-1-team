# basic-guide

코드를 처음 보는 사람이 **개발 지식 없이** 단계별로 이해하도록, 단일 HTML 웹 앱을 생성한다.

## 산출물

- 경로: `./docs/basic_guide.html` (폴더가 없으면 생성, 이미 있으면 덮어쓰기 전에 사용자에게 알린다)
- 단일 파일. 외부 라이브러리·CDN·이미지 의존 없이 HTML + CSS + JS 를 한 파일에 담는다. 더블클릭만으로 열려야 한다.

## 진행 순서

1. **코드 파악**: 프로젝트의 화면, 서비스, 도메인 규칙, 계산 로직, 설정 데이터를 읽어 "업무가 무엇인지"를 파악한다. 파일 목록 나열이 아니라 요구사항(누가, 무엇을, 왜)을 뽑는 것이 목적이다.
2. **내용 설계**: 아래 3개 탭 구조에 맞춰 내용을 정리한다.
3. **HTML 작성**: `./docs/basic_guide.html` 로 저장한다.
4. **검증**: 파일이 생성됐는지, 탭 3개와 인터랙티브 요소가 모두 들어갔는지, 금지 용어가 없는지 확인한다.
5. **보고**: 파일 경로와 탭별 한 줄 요약만 짧게 알린다. 문서 내용을 채팅에 다시 풀어 쓰지 않는다.

## 탭 구성 (정확히 3개, 이해 단계 순서)

| 탭 | 질문 | 담을 내용 | 인터랙티브 요소 (탭당 1개 이상) |
|---|---|---|---|
| 1. 한눈에 보기 | 이 시스템은 무엇인가? | 한 줄 요약, 등장인물/대상, 사용자가 하는 일의 흐름 | 단계 카드를 클릭하면 설명이 펼쳐지는 업무 흐름도 |
| 2. 핵심 규칙 | 어떤 기준으로 움직이는가? | 업무 규칙, 기준 정보(수치·제약), 비용/시간 계산의 의미 | 값을 바꾸면 결과가 바로 바뀌는 간단한 체험 계산기 |
| 3. 직접 따라가기 | 실제로 쓰면 어떻게 되는가? | 대표 시나리오 한 건을 처음부터 끝까지, 주의할 상황(충돌, 거부, 되돌릴 수 없는 작업) | 단계별 "다음" 버튼 시나리오 시뮬레이션, 퀴즈 또는 체크리스트 |

프로젝트 성격에 맞게 탭 제목·내용은 조정해도 되지만, **개수는 3개, 순서는 쉬운 것에서 깊은 것으로** 유지한다.

## 작성 원칙

- **독자**: 개발 지식이 없고, 이해에 많은 에너지를 쓸 수 없으며, 나중에 코드 리뷰를 편하게 하려는 사람.
- **금지**: 클래스·함수·변수·파일명, 프레임워크·DB·API 같은 개발 용어, 코드 조각. 불가피하면 업무 용어로 바꿔 쓴다.
- **허용**: 화면 이름, 업무 용어, 숫자와 예시, 비유.
- 한 화면에 한 가지 메시지. 문장은 짧게, 표와 카드로 시각화한다.
- 탭 전환 시 스크롤 위치를 맨 위로 되돌리고, 키보드(좌우 방향키)로도 탭을 이동할 수 있게 한다.
- 체험 계산기·시나리오의 수치와 규칙은 **실제 코드의 값과 로직**을 따른다. 코드에서 확인하지 못한 값은 지어내지 말고 생략하거나 "예시"라고 표시한다.
- 화면 폭이 좁아도 읽히도록 반응형으로 만들고, 라이트/다크 모두에서 글자가 잘 보이게 한다.
- 한국어로 작성한다.

## 완료 기준

- `./docs/basic_guide.html` 이 존재하고 브라우저에서 바로 열린다.
- 탭 3개, 탭마다 인터랙티브 요소 1개 이상이 동작한다.
- 본문에 개발 용어와 코드가 없다.

# basic-guide

개발 지식이 없는 사람이 3개 탭으로 단계별로 이해하는 단일 HTML 파일을 만든다.

- 출력: `docs/understand/김재연/basic_guide.html` (사용자가 다른 경로를 주면 그 경로. 이미 파일이 있으면 덮어쓰기 전에 알린다)
- 기준 틀: `assets/template.html` (완성본). 처음부터 쓰지 말고 이 파일을 복사해 내용만 현재 코드에 맞게 고친다.
- 서버·외부 라이브러리 없이 HTML/CSS/JS 하나. 더블클릭으로 열려야 한다.
- 언어는 한국어. 코드·파일명·클래스명·기술 용어(서버, DB, API 등)는 화면에 쓰지 않는다.

## 순서

1. **코드 읽기**: `src/main/java/com/example/demo` 의 `simulation/Planner.java`, `service/BatteryService.java`(특히 `initDefaults`, `confirm`, `changeStatus`), `entity/OrderStatus.java`, `entity/Country.java` 를 읽어 현재 규칙과 기본값을 확인한다. 기억이 아니라 현재 코드 기준이다.
2. **틀 복사**: `assets/template.html` 을 출력 경로로 복사한다.
3. **내용 대조·수정**: 아래 3탭 기준과 현재 코드를 비교해, 달라진 값만 고친다.
   - 탭 3 `factories` 배열: 나라별 하루 최대 생산량·쌓아 둘 수 있는 한도·셀당 원가 (`initDefaults`)
   - 탭 3 배 척수·최대 척수 문구 (`initDefaults`, `MAX_SHIPS`)
   - 탭 2 `next` 상태 전이표 (`OrderStatus.next()`), 입력 범위 문구 (`Planner.MAX_TOTAL_K`)
   - 퀴즈 정답·해설이 위 값과 맞는지
4. **점검**: 생성된 HTML에서 금지 용어(서버, 데이터베이스, API, 코드, 클래스, 함수, 트랜잭션, 버전 충돌 등)를 검색해 남은 것이 없는지 확인한다. 가능하면 브라우저로 열어 탭 전환·카드·단계 이동·상태 버튼·슬라이더·퀴즈가 동작하는지 본다.
5. 만든 파일 경로와 "간이 계산기는 실제 결과의 단순화 버전"이라는 점을 한 줄로 알린다.

## 3탭 구성 기준

각 탭은 질문 하나에 답하고, 1~2분 안에 볼 분량이다. 탭 아래에 "다음 탭으로" 버튼을 둔다.

1. **큰 그림 — "이게 뭐 하는 거야?"**: 한 줄 요약, 비유(택배 기사가 창고를 도는 일), 등장인물 카드(공장·배·주문·한국·운항 계획). 인터랙션: 카드 클릭으로 설명 열기/닫기.
2. **사용 흐름 — "사람이 뭘 하지?"**: 로그인 → 수량 입력 → 세 경로 비교 → 확정 → 상태 관리 5단계(이전/다음 버튼), 주문 상태 체험(현재 상태에서 갈 수 있는 버튼만 활성). 인터랙션: 단계 이동, 상태 전이.
3. **계산 원리 — "컴퓨터는 어떻게 정하지?"**: 핵심 규칙 4개(한도, 여러 번 방문, 한 나라 한 배, 세 기준 비교), 나라별 슬라이더 간이 계산기(방문 횟수 = 올림(주문 ÷ 한도), 최소 생산 일수 = 올림(주문 ÷ 하루 최대), 생산비 = 주문K × 1000 × 셀당 원가), 퀴즈 3문항. 화면에 "간이 예시이며 실제 계산은 더 복잡합니다"를 표시한다. 이동 일수·운항비는 코드와 대조하지 않은 채 계산기에 넣지 않는다.

## 원칙

- 쉬운 말만 쓴다. 도메인 용어는 K(셀 1,000개), 억 원, 쌓아 둘 수 있는 한도 정도로 제한한다.
- 이 스킬은 HTML만 만든다. 앱 코드는 수정하지 않는다.

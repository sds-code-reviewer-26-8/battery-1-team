# INTENT — 배터리 주문·생산·선박 운영 계획 프로그램

> PRD가 "무엇을"이라면 이 문서는 "왜"를 적는다.
> 근거 표시: **[요구사항]** 원문에 직접 적힘 / **[코드]** 코드·주석에서 확인

## 1. 목적

### 1.1 풀려는 문제
DSD는 4개국 공장을 직접 운영하면서 배를 빌려 물량을 한국으로 들여온다. 주문이 들어올 때마다 "어느 공장에서 얼마나 만들고, 배를 어떻게 돌려 실어 올지"를 정해야 하고, 이 결정이 생산원가와 선박 임차비(하루 약 1억 원)를 크게 좌우한다. 공장마다 하루 생산량, 창고 크기, 원가, 거리가 달라서 사람이 따지기 어렵다.

이 일을 경로 여러 안을 즉시 계산해 비교하고, 결정한 내용을 그대로 남기는 일로 바꾼다.

### 1.2 역할의 경계
- 경로는 담당자가 고른다. 시스템은 선택지를 나란히 보여 주고 계산을 맡는다.
- 선택한 계획을 그대로 기록해 두어, 나중에 "그때 왜 이렇게 정했는지" 다시 볼 수 있게 한다.

## 2. 설계 의도 — 왜 이렇게 만들었나

| 판단 | 이유 | 근거 |
|---|---|---|
| 경로를 여러 안으로 비교해 보여 주고 사람이 고르게 한다 | 비용·속도 중 무엇을 우선할지는 업무 상황마다 달라 사람에게 넘긴다 | [코드] |
| 확정 시 서버가 같은 입력으로 **다시 계산**한다 | 화면이 보낸 값은 낡았거나 조작됐을 수 있다 | [코드] `BatteryService.java:220-221` 주석 "클라이언트 값은 믿지 않는다" |
| 시뮬레이션 뒤 마스터가 바뀌면 **확정을 거부**한다 | 사람이 본 숫자와 저장되는 숫자가 달라지는 것을 막는다. 불편해도 다시 계산하게 하는 편이 안전하다 | [코드] 마스터 버전 |
| 확정 주문에 **당시의 마스터 값과 계획 전체**를 저장한다 | 마스터는 계속 바뀐다. 과거 주문을 현재 값으로 다시 계산하면 기록이 거짓이 된다. 증빙과 재현성 | [코드] `StoredPlan`, `Order.planJson` |
| 상태 전이를 제한하고 **낙관적 락**을 쓴다 | 잘못된 상태로 돌아가거나 두 사람이 동시에 바꿔 조용히 덮어쓰는 일을 막는다 | [코드] `OrderStatus`, `Order.@Version`, `BatteryService.java:274-276` |
| 마스터는 **전부 아니면 전무**로 저장한다 | 일부만 바뀐 기준 값이 계산에 쓰이지 않게 하고, 한 번에 고치게 한다 | [코드] `BatteryService.java:108-111` |
| 완료·취소는 **마지막 상태**다 | 끝난 주문의 이력이 흔들리지 않게 한다 | [요구사항] [코드] `OrderStatus` |
| 취소하면 **주문은 삭제하고 이력은 보관**한다 | 취소된 주문은 운영 대상이 아니라 목록에서 치우되, 누가 언제 무엇을 바꿨는지는 이력으로 남긴다 | [코드] `BatteryService.java:295`, `OrderStatusHistory`(주문과 외래키 없이 `orderId`만 보관해 주문이 삭제돼도 이력이 남는다) |
| 금액은 **원 단위 정수**로 다루고 억 원은 표시용으로만 쓴다 | 소수 오차를 없애고 큰 금액을 한눈에 읽게 한다 | [코드] `long`, `WON_PER_EOK` |
| **한국 대기는 무료**이고 배는 늦게 출항한다 | 한국 항만에 서 있는 동안은 임차비가 없으므로, 일찍 나가 항구에서 기다리게 하지 않고 한국에서 기다렸다 출항해 항해 일수(=임차비)를 줄인다 | [요구사항] [코드] `Planner.java:23-24` |

## 3. 이번 범위

| 항목 | 내용 | 근거 |
|---|---|---|
| 수량 단위 | 일일 최대 생산량 같은 값은 **정수 K만 처리**한다. 원문 예시의 소수(0.1K)는 지원하지 않는다 | [코드] `BatteryService.java:137` |
| 계정 | **회원가입은 없고** `admin` 계정으로만 사용한다 | [코드] `AppController.java:30` |
| 공장별 배분 | **자동 배정 추천은 없다.** 공장별 수량은 담당자가 정한다 | [코드] `order-new.js`의 게이지 조정 |
| 시뮬레이션 | 경로 계산 알고리즘은 현재 규칙 그대로 둔다 | [코드] `Planner` |
| 주문 입력 | 주문 시 **고객사와 납기는 입력받지 않는다** | [코드] `Order`에 해당 필드 없음 |
| 취소 주문 | 취소하면 주문은 삭제하고 이력만 보관한다 | 2장 참고 |

2요청 원문

Controller,Service,Repository가 현재 하나의 클래스로만 작성되어있는데, 하나의 파일에 너무 많은 내용이 들어가지 않도록 업무 종류별로 파일을 분리하는 refactoring을 진행해줘

3이해 점검

배경 · 어떤 상황인가이해함

Controller 는 AppController(198줄) 한 클래스에 로그인·주문·마스터·API 매핑이 모두 있고, Service 는 BatteryService(303줄)에 마스터 관리·시뮬레이션·주문 확정·상태 변경이 섞여 있습니다. Repository 는 MasterRepositories, OrderRepositories 라는 final 컨테이너 클래스 안에 인터페이스가 중첩되어 있습니다.

근거: AppController.java 매핑 목록(52~182줄), BatteryService.java 메서드 목록, repository/*.java

목적 · 왜 필요한가이해함

한 파일이 커지는 것을 막아 가독성·유지보수성을 높이려는 것입니다. 화면·API·계산 결과는 그대로이며, 성공은 기존 테스트가 그대로 통과하고 파일이 업무별로 나뉘었는지로 판단합니다.

근거: 요청 문장 · 보유 테스트(JUnit, Playwright E2E)

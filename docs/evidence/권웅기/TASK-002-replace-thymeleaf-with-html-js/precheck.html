현재 화면 6개(login, orders, order-detail, order-new, master, fragments)는 Thymeleaf 가 서버에서 HTML 을 만듭니다. 주문 추가 화면만 이미 JS(order-new.js, anim.js, planview.js)와 JSON API(/api/simulate, /api/orders, /api/master)를 씁니다. 목록·상세·로그인·마스터 저장은 JSON API 가 없고 폼 POST 와 리다이렉트, flash 메시지에 의존합니다.

목적 · 왜 필요한가✓ 이해함

프론트엔드를 서버 템플릿에서 분리해 정적 HTML/JS 로 만들고 서버는 JSON API 만 제공하게 하는 구조 연습입니다(브랜치명 refactoring-practice). 끝나면 Thymeleaf 의존성과 템플릿이 없고, 사용자가 보는 화면과 동작은 그대로입니다. 성공 기준은 기존 JUnit·E2E 결과가 baseline 과 같은 것입니다.
